# QuizSniper

截图答题助手：**离线 OCR 识题 → 本地题库优先命中 → 大模型兜底**，带图形界面与命令行两种用法。Windows 桌面工具，全程本地截图与本地 OCR，只有题库未命中且你开启了模型时才会联网。

> v2 是一次完整重构：单文件 1286 行拆成 `quizsniper/` 包，补齐图形界面，并修掉了原实现里的 12 处逻辑缺陷（见「相对 v1 的改动」）。

---

## 界面

启动后是一个深色双栏窗口：

- **左栏**
  - **截图来源**：选择目标窗口（下拉列表，跟随刷新）、设置识别区域（框选 / 预览 / 重置）。
  - **识别结果**：大字显示答案，标注来源（题库 / AI·文本 / AI·图片）、命中方式与相似度；下方是 OCR 识别出的题目原文、OCR 变体与各阶段耗时；最下面是操作按钮（截图识别 / 连续识别 / 复制答案 / 清空）。
- **右栏**四个标签页
  - **设置**：模型（提供方 / Base URL / API Key / 模型 ID，可一键拉取模型列表）、题库阈值、OCR 预处理、请求参数、全局热键、连续识别间隔。
  - **题库**：检索、查看、新增、修改、删除、导入、导出，只读题库与用户题库用颜色区分。
  - **日志**：分级实时日志，可过滤、导出。
  - **记录**：本次会话的答题历史与命中率统计，双击复制答案。

底部状态栏常驻显示当前状态与已注册的全局热键。

## 功能

- **题库优先，AI 兜底**：题库命中直接出答案（毫秒级），未命中再调模型。
- **纯题库模式**：完全不配模型也能用，离线 OCR 本地识题。
- **文本优先的 AI 兜底**：题库未命中时先把 OCR 文本发给模型（省 token、更快），文本失败再退回整图多模态。
- **两种区域定位**：`跟随窗口`（相对窗口左上角，窗口移动后区域自动跟随）与`屏幕绝对`（固定屏幕坐标）。
- **可视化框选**：把「即将被截图的那一块」原样显示出来让你拖框，所见即所得，不受 DPI 缩放影响。
- **全局热键**：默认 `F8`，在任意程序前台都能触发识别；窗口内 `F8` 同样有效。
- **连续识别**：按设定间隔自动截图识别，适合连续答题。
- **诊断信息**：每次识别都给出 OCR 变体、置信度、命中模式、相似度与最接近的 3 条题库题目，方便补题。

## 快速开始

要求 **Windows + Python 3.10+**（推荐 3.11 / 3.12 / 3.13 官方安装包，自带 Tkinter）。

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python run.py                # 图形界面
python answer_helper.py      # 命令行（保留旧手感）
```

可选：先跑一次自检，确认 OCR 与字体环境正常（不联网、不截屏）：

```bash
python tools/selftest.py
```

输出两行 `[OK]` 即表示识别链路可用。

## 使用流程

1. `python run.py` 启动。
2. 「设置」页填好 API Key / Base URL / 模型（只用题库可跳过，把「启用大模型答题」取消勾选）。
3. 「截图来源」里选目标窗口 → 点「框选」，拖出一个只包含题目与选项的矩形 → 确定。区域会存进配置，下次启动自动恢复。
4. 回到题目界面按 `F8`（或点「截图识别」）：命中题库直接显示答案；未命中且有模型时自动走 AI。
5. 答案需要粘贴时点「复制答案」，或在设置里打开「识别成功后自动复制」。

### 命令行

```bash
python answer_helper.py
```

启动时依次询问：是否启用模型 → 题库是否优先 → 是否固定窗口/区域。之后回车识别，`q` 退出，`w` 换窗口，`r` 重设区域，`s` 看统计。

## 识别与匹配

### OCR

RapidOCR（onnxruntime）本地推理。识别前会生成多个图像变体并投票：

1. 原图（转 BGR）；
2. 灰度 + 放大 `ocr_scale` 倍 + 自动对比度（**不做硬二值化**）；
3. 若检测到暗底（平均亮度 < 110）再追加反色版本。

取「文本行数最多、平均置信度最高」的一份结果，避免单一预处理把整题打死。行序按 `行高中位数 × 0.55` 聚类，同行内按 x 排序。

### 规范化

```
NFKC 归一 → 去掉【答案】/答案：等标记 → 只保留字母、数字、汉字
```

题库存 `A. 选项` 前缀、OCR 不产出时，额外生成「仅题干」候选对齐错位。

### 四段式匹配

| 模式 | 判定 | 说明 |
|---|---|---|
| `exact` | 规范化后完全相等 | 直接返回，短路 |
| `contains` | 一方完整包含另一方，且短串 ≥ `min_contains_length` | 取最长候选，防「体育」命中「体育理论」 |
| `substring` | 较短串被匹配块覆盖比例 ≥ `substring_threshold` | 容忍 OCR 漏字/多字 |
| `similarity` | 编辑相似度 ≥ `similarity_threshold` | 兜底 |

规范化长度小于 `min_query_length` 的文本直接跳过模糊匹配——「下列说法正确的是」这种通用题干不该命中任何题。

### 为什么阈值看起来偏低

旧版用 `SequenceMatcher` 默认参数，序列超过 200 时 `autojunk=True` 会把高频字符当噪声丢弃，中文题干里的「的」「是」正好中招，长题相似度被系统性低估，只能靠调低阈值硬扛。v2 一律 `autojunk=False`，分数回到真实水平，0.72 的阈值比旧版更严格而不是更松。

## 题库

两个来源，职责分离：

| 位置 | 可写 | 用途 |
|---|---|---|
| `question_banks/*.json` | 否 | 内置/导入的资料题库，界面上灰显 |
| `answer_question_bank.json` | 是 | 界面里新增、修改、删除都写这里 |

界面保存时**只回写用户题库**，不会覆盖只读文件；两条来源重复时按规范化题干去重，别名合并。

单条格式：

```json
{
  "entries": [
    {
      "question": "以下哪项属于典型的有氧运动方式",
      "answer": "B",
      "aliases": ["以下哪项属于典型有氧运动方式"]
    }
  ]
}
```

- `question`：题干（可以带选项，程序会自动截出题干候选）
- `answer`：答案文本，原样展示
- `aliases`：可选，OCR 常见误识别版本，能显著提升命中率

## 相对 v1 的改动

### 逻辑缺陷修复

1. **OCR 硬二值化**：`point(255 if p > 180 else 0)` 砍掉抗锯齿边缘，深色界面整图变黑 → 改为多变体投票，暗底自动反色。
2. **`autojunk=True`**：长题干高频字被当噪声丢弃，相似度系统性偏低 → 显式关闭。
3. **子串相似度 O(n²·m)**：滑动窗口逐窗调 `ratio()`，797 条题库单次匹配数百毫秒 → 改为一次 `get_matching_blocks` 取覆盖率，并加字符集预筛与结果缓存。
4. **`GetWindowRect` 包含阴影边框**：Win10/11 下多截 7~16px 透明边，区域整体偏移 → 改用 `DWMWA_EXTENDED_FRAME_BOUNDS`。
5. **副屏截图全黑**：`ImageGrab.grab()` 默认只抓主屏 → 统一 `all_screens=True`。
6. **窗口列表硬截断 20 个**：第 21 个窗口永远选不到 → 返回完整列表。
7. **先展示后重查**：`select_window_by_index` 重新枚举窗口，序号错位会选错窗口 → 从同一份列表取。
8. **配置半残即丢弃**：`load_saved_config` 要求四个字段齐全，否则整份配置作废（连背景提示词一起丢） → 逐字段容错，未知字段忽略。
9. **错误判定靠子串**：`"500" in message` 会把模型名里的数字当服务端错误 → 改成按 HTTP 状态码分类。
10. **每题一次 TLS 握手**：没有复用连接 → `requests.Session` + 连接池 + 自动重试。
11. **只读题库被回写**：整份列表落盘会覆盖内置题库 → 只写用户题库。
12. **行序错乱**：把 y 坐标绝对值当行高用，容差被放大到整屏，选项跑到题干前面 → 用真实行高（box 高度）中位数。

### 结构改动

- 单文件 → 8 个核心模块 + 9 个界面模块，CLI 与 GUI 共用同一套 `Solver`。
- 新增 Tkinter 图形界面：可视化框选、题库管理、实时日志、答题记录、连续识别、全局热键。
- 所有耗时操作（枚举窗口、OCR、识别、拉模型、加载题库）走后台线程，界面不假死。
- 新增 19 个单元测试与一个端到端自检脚本。
- 配置 / 题库写入改为临时文件 + 原子替换，中途崩溃不会留下半截 JSON。

## 常见问题

**找不到窗口？**
目标程序不能最小化；列表里没有就点「刷新」，或先不选窗口用全屏截图确认流程。

**OCR 识别不准？**
尽量只框住题目与选项区。小字号把「放大倍数」调到 2.0~3.0；深色界面确认「暗底自动反色」开着；高频题型把识别错的文本加进该题 `aliases`。

**题库总是不命中？**
看「识别结果」下方的「最接近的题库题目」和相似度：0.6~0.7 之间说明只差一点，把 OCR 文本补成别名；低于 0.5 说明题库里没有这题。

**模型报 401/403？**
API Key 或 Base URL 不对，把 Base URL 的 `/v1` 前后缀对齐提供方文档；报 429 就换模型或稍后再试。

**界面字体很小/很大？**
程序按窗口 DPI 校正过缩放；仍有问题检查系统缩放比例，125%、150% 都已适配。

## 已知限制

- 仅 Windows：依赖 `RegisterHotKey`、DWM 边界与桌面截图。
- 目标窗口最小化时无法截图（Windows 不渲染最小化窗口）。
- 部分全屏独占游戏（DirectX 全屏）截不到，需要改为无边框窗口。
- OCR 对艺术字、竖排文字、低对比度水印效果有限。
- 题库匹配是文本相似度，不理解语义；纯改写过的题干仍可能不命中。
